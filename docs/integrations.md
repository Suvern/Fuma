# 第三方接入

先完成[部署初始化](deployment.md)，再按启用功能配置提供方。凭据通过后台输入，由服务端加密保存；不要放进前端环境、仓库示例或问题报告。本指南描述当前适配器的能力，实际权限须在自己的提供方账号中验证。

## 飞书登录与机器人

当前接入飞书国内版企业自建应用，每套 Fuma 绑定一个可信租户。SSO 和机器人使用同一个应用；没有通用 OIDC 或海外 Lark 配置入口。

1. 准备企业自建应用，启用登录和机器人能力，将需要登录的用户加入应用可用范围，完成企业内发布。
2. 登记后台显示的 OAuth 回调地址。站点为 `https://fuma.example.com` 时，回调为 `https://fuma.example.com/api/v1/auth/feishu/callback`。
3. 本地管理员在“飞书设置”录入 App ID 和 App Secret，发起 OAuth 租户验证，核对候选租户并确认绑定。单纯保存凭据不会激活可信租户。
4. 用同租户测试用户登录，并用不具备资格的用户验证拒绝路径。后台可为飞书成员授予管理员或指定应用的维护者权限；管理权限不替代私有下载资格。
5. 将同应用机器人加入测试群，检查机器人身份、同步群列表，选择群并显式发送测试卡片。群列表只包含机器人所在群。

配置权限时，依据以下实际调用检查控制台的对应授权；获取应用令牌成功不代表所有能力可用：

| 能力 | 当前适配器调用 |
| --- | --- |
| OAuth 换取用户身份 | `/open-apis/authen/v2/oauth/token`、`/open-apis/authen/v1/user_info` |
| 获取应用令牌 | `/open-apis/auth/v3/tenant_access_token/internal` |
| 核实机器人 | `/open-apis/bot/v3/info/` |
| 获取机器人所在群 | `/open-apis/im/v1/chats`，支持完整分页 |
| 发送群卡片 | `/open-apis/im/v1/messages`，以 `chat_id` 为接收者 |

修改可用范围、应用版本或权限后，应重新验证登录与发卡片。当前没有个人消息收件人配置。投递成功只表示飞书接受请求；未知结果不会自动重发，手动重试前须确认可能产生重复消息。

## GitHub 仓库和 Release

支持 PAT 和 GitHub App Connector，当前适配器面向 GitHub.com，未提供 GitHub Enterprise Server 自定义域名入口。

- PAT 应限定到所需仓库，具备读取 Contents 的权限；需要核实 Actions 构建时还须读取 Actions。私有仓库还受组织授权策略约束。
- GitHub App 使用应用身份、安装标识和私钥，安装到目标仓库，并授权所需的 Contents / Actions 读取能力。
- 在后台创建 Connector，执行连接及权限检查，再为 Fuma 应用验证并绑定仓库。不要用仓库可见性推断附件和 Actions 权限已经可用。

GitHub Releases 页面同步完整快照，支持 Tag、预发布状态、文件名和排除规则。可用 `sample-*.apk, *.ipa` 包含所需产物，再用 `*unsigned*` 排除未签名文件。规则区分大小写，排除规则优先；草稿和不受支持的附件不能分发。

普通规则导入生成 Debug 条目，文件在需要时缓存；它不会自动创建正式版本发布。自动同步默认关闭，启用后会处理历史匹配产物，再定期检查。Scheduler 和 Worker 必须持续运行；来源去重不意味着重新启用已停用条目。正式包持久化与版本发布使用独立操作。

## GitHub Actions 回调

参考[源项目工作流示例](../deploy/github-actions-example.yml)，将示例调整后放到构建 APK 的源仓库。它不是 Fuma 自身的 CI。

1. 在 Fuma 应用内创建 Actions 规则，配置精确的 workflow 路径、可信分支或 Tag、附件规则和目标群。
2. 将规则提供的完整回调 URL 保存为源仓库变量 `FUMA_CALLBACK_URL`，将一次性显示的规则令牌保存为 GitHub Actions Secret `FUMA_CI_TOKEN`。
3. 工作流构建并上传 Release 附件后，提交仓库、run、attempt、commit、Release 和附件标识；不提交下载 URL、任意 shell 或收件群参数。
4. 收到 `202` 后结束回调步骤。Fuma 等整个 workflow run 成功，再核实来源、处理文件并投递；同一 workflow 不得等待 Fuma 完成，否则会互相等待。
5. 在构建事件页检查逐阶段结果，确认文件可下载，再检查真实群卡片。

回调令牌只对所属规则生效，轮换或撤销后更新仓库 Secret。回调受理不表示构建、缓存或投递成功；后台会通过 GitHub 再核实仓库、workflow、可信 ref、SHA、运行次数与附件归属。重复回调复用事件，不能借此强制重复通知。

## COS / OSS 对象存储

正式包可保存在本机或私有 COS / OSS；公开云发布使用独立公开副本。当前仅支持厂商标准地域端点，不支持通用 S3、MinIO、自定义域名或 CDN 配置。

1. 准备专用存储位置和路径前缀；原件使用私有访问，公开副本使用独立位置。COS 桶名须包含厂商分配的 APPID，地域填写厂商标识。
2. 准备限定桶及路径范围的凭据。按实际功能授权读取版本控制状态、上传、读取元信息、下载、删除、设置对象 ACL 及分片上传所需能力。
3. 在存储设置中录入提供方、地域、桶、前缀和凭据，执行检查。公开副本桶必须从未启用版本控制；已暂停版本控制的桶也会被拒绝。
4. 用可丢弃测试包完成私有入库、授权下载、公开发布和收回，检查真实对象权限及匿名访问结果。

发布使用 `public-read` 副本，原件保持私有。配置桶级公开访问阻断时需要与使用目的协调，不能为了测试开放私有原件桶。云侧权限、生命周期和版本策略改变后应重新验收。

收回公开副本是异步操作，失败状态需要处理；撤销页面或授权不能收回已下载的文件。临时签名链接在其有效期内可能继续可用，不应作为固定分享地址。云直链的实际读取次数不等于 Fuma 记录的下载授权次数。

## 接入验收边界

自动化测试中的提供方替身只能验证请求与错误处理。真实租户范围、私有仓库权限、workflow 成功后的处理、群消息投递及云公开对象收回，必须使用自己的测试资源完成验收。本轮文档重建未执行这些外部接入操作。
